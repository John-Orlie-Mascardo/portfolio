02 Featured capstone

LitterSense

IoT + Web application

LitterSense is our capstone IoT monitor for recording litter-box visits and flagging unusual activity on a web dashboard. I built the hardware and helped connect it to the app. Our team used React, Firebase, and ESP32 hardware, then tested the assembled prototype with cats.

From a cat’s visit to the dashboard

Visit project ↗ Opens the live app · Sign-in required

What the system does

  • Records litter-box sessions and flags unusual activity.
  • Monitors odor to help identify when litter needs changing.
  • Offers live viewing and individual cat profiles.
  • Provides activity reports and AI-generated behavior insights.

How I tested the system

  • I tried features on the prototype and compared what happened with what we expected.
  • I shared problems with teammates and tried the same features again after fixes.
  • I helped troubleshoot the connection between the hardware and web app, including changes to the frontend and backend.
Academic project objectives

Design, develop, and evaluate an IoT-enabled feline health monitoring system for Filipino cat owners, combining camera-equipped ESP32 hardware, multiple sensors, and a React-based Progressive Web Application (PWA).

  1. Analyze household monitoring practices and the clinical, infrastructure, and technology limitations of manual observation and global commercial platforms.
  2. Integrate a modified litter box, RFID identification, ultrasonic and gas sensors, camera modules, Firebase cloud services, and a React PWA with real-time anomaly alerts and PDF/CSV reports.
  3. Evaluate sensor accuracy and reliability, RFID identification, anomaly thresholds, and PWA functionality under simulated Philippine network conditions.
  4. Deploy the prototype in a real household and evaluate individual cats’ elimination patterns, report usability, and reliability under Philippine infrastructure constraints.

Manual QA

Hands-on testing experience from our LitterSense capstone.

Manual QA sample · Account recovery

Date: November 11, 2026 · Environment: Windows 11, Google Chrome.

  1. AD-01 · Recover with a new email Passed

    Precondition
    Ownership could be verified through the approved process.
    Steps
    Open Users, view the user, verify ownership, enter a new email, and request a reset link.
    Expected
    The user receives a reset link, sets a new password, and can sign in with the new email.
    Actual
    The link arrived; the user set a new password and signed in with the new email.
    Retest
    Passed.

  2. AD-02 · Recover with the same email Passed

    Steps
    Leave the new email field blank and request a reset link.
    Expected
    The link arrives, the user can set a new password, and the installed app redirects to sign-in on phone and PC.
    Actual
    The link arrived, the user set a new password, and the installed app redirected to sign-in on phone and PC.

  3. AD-03 · Verification note under 10 characters Passed

    Steps
    Enter a verification note with fewer than 10 characters.
    Expected
    The reset button stays unavailable until the note meets the minimum length.
    Actual
    The reset button stayed greyed out and could not be clicked.

  4. AD-04 · Open a link after 30 minutes Passed

    Steps
    Wait more than 30 minutes, then open the reset link.
    Expected
    The expired link is rejected and the password remains unchanged.
    Actual
    The page reported the link as invalid or expired; the password did not change.

  5. AD-05 · Reuse a reset link Passed

    Steps
    After successfully using a reset link, open the same link again.
    Expected
    The used link is rejected and the password remains unchanged.
    Actual
    The page reported the link as invalid or expired; the password did not change.
